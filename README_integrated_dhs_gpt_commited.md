# Time Keeper 통합본

## 실행

이 파일들이 있는 BusFlow 폴더에서:

```bash
python app_integrated_dhs_gpt_commited.py --open-browser
```

Windows에서는 `run_integrated_dhs_gpt_commited.bat`를 실행할 수 있습니다.
주소: http://127.0.0.1:5001
HTML을 더블클릭하는 대신 이 주소로 접속합니다. 기존 `app.py`/overlay와 동시에 같은 포트로 실행하지 않습니다.

새 진입점은 기존 소스와 DB를 읽는 독립 WSGI 앱입니다. 기본 실행은 Python 표준 라이브러리만 사용하며 기존 Flask 파일, RF pickle 모델, 수집기를 변경하지 않습니다. 한국 공휴일 구분은 기존 `requirements_dhs_gpt_commited.txt`의 `holidays` 패키지를 사용합니다. 없으면 주말만 구분하고 화면에 알립니다. `.env`의 기존 `DATA_API_KEY`를 읽습니다. 날씨는 키가 필요 없는 Open-Meteo 시간별 예보를 사용합니다.

## 이번에 연결한 기능

- 서버의 기존 `config.py`를 기준으로 승차 후보를 제공하고 A/B 모두 LIVE 조회.
- 기흥구·강남구 대표 지점 날씨 카드. 선택 날짜/시간 예보와 현재 시간대 예보를 구분.
- Open-Meteo의 rain + showers 시간별 누적값(선택 시간대 종료시각)을 사용. 눈은 강수 가중치에 억지로 포함하지 않음. 눈·특수 이벤트 모델 없음.
- 미래 배차·좌석은 기존 DB의 과거 기록에서 추정. 같은 차량 반복 관측을 중복 승차 표본으로 세지 않음.
- 데이터 선택은 검색 날짜 전, 동일 계절/요일/시간을 우선하고 동일 평일·휴일/시간으로 범위를 넓힐 경우 근거 표시.
- 같은 차량의 날짜/회차(정류장 순번 감소)를 구분해서 승하차 시간을 짝지음.
- **총 이동시간 = 앞 구간 기존시간 + 기흥역→신논현역 범위의 기존시간 × 강수 가중치 + 뒤 구간 기존시간.**
- 중간에 하차하면 확인된 대상 구간 내 해당 부분에만 가중치 적용. 퇴근/대상 구간 진입 06~08시 밖에는 기존 기록 사용.
- 10분 간격의 정류장 도착 시점을 검색. 과거 배차에서 초기 대기와 만석 추가 대기를 추정. 미래의 실제 운행시각표를 확보한 것으로 표시하지 않음.
- 마감 초과 후보 제외. 데이터 부족과 탐색한 후보의 도착 불가능을 구분.
- 시간 우선은 최종 도착시각으로 정렬. 안정 우선은 표본 부족 여부, 만석 빈도, 과거 혼잡도, 마감 여유를 비교.
- 2위 카드를 클릭하면 2위 상세가 상단에, 아래에는 BEST/3위/4위가 원래 순서로 표시. 계산 순위는 변경하지 않음.
- 실패 시 가짜 좌석·도착시간·추천을 생성하지 않음. LIVE의 오래된 기록은 과거 스냅샷으로 표시하고 카운트다운 중지.

## 기존 DB 연결과 실제 검증 범위

실행하는 PC의 `data` 폴더에 기존 파일을 그대로 둡니다:

- `busflow.db`: congestion (5001)
- `busflow_5003.db`: congestion (5003)
- `realtime.db`: realtime_location, realtime_arrival_a/b 또는 realtime_arrival, 선택적으로 travel_time_stats

GitHub main에는 realtime.db와 busflow_5003.db가 없습니다. 2026-09-18 GitHub Actions에서 실제 busflow.db 및 루트 weather.db를 읽어 테이블·건수·기간을 확인했고, 실제 XLSX를 이용한 회귀검사를 추가했습니다. 5003 혼잡도는 날짜별 XLSX로 보완됩니다. 전체 이동시간·예측 정확도는 누락된 운행 자료 때문에 검증하지 못했습니다. 합성 SQLite fixture는 코드 검증용 임시 폴더에서만 사용하며 앱에 제공하지 않습니다.

기존 travel_time_stats는 노선·시간대만 키로 가지고 있으므로 **기흥역→신논현역 A 노선에만** 제한적으로 재사용합니다. 다른 목적지에 같은 시간을 복사하지 않습니다. 그 밖의 구간은 realtime_location에 실제 양끝 관측과 해당 방향 정류장 식별이 있어야 합니다. B의 반대편 정류장 ID를 A에서 복사하지 않습니다. 기존 이름 매핑 또는 관측 station_name으로 고유하게 확인되지 않는 목적지는 제외합니다.

고속도로로 구한 가중치를 기흥역→신논현역 전체에 적용하는 것은 사용자 요청에 따른 **근사 모델**입니다. 시내 구간과 고속도로가 같은 지연률을 보인다는 실증은 없고, 기존 이동시간 표본에 이미 비가 포함된 경우 강수 효과가 중복될 수 있습니다. 안전도는 도착 확률이 아니며 표본이 적으면 '주의'로 제한합니다. 무조건 승차/정시 도착을 보장하지 않습니다.

현 버전의 경로 추천은 과거 기록 기반 예측입니다. 현재 차량의 좌석·도착은 별도 LIVE INFO에서 조회합니다. 도보시간, 미래 확정 운행시각표, 퇴근용 날씨 모델, 이벤트 영향은 포함하지 않습니다.

## 검증

```bash
# 외부 API를 호출하지 않는 회귀 테스트
python -m unittest discover -s tests -p 'test_*dhs_gpt_commited.py' -v
node tests/test_ui_integrated_dhs_gpt_commited.js
```

`BUSFLOW_OFFLINE=1`을 설정하면 버스/날씨 외부 호출을 차단할 수 있습니다. 실제 API 호출 검증은 사용자 요청에 따라 보류했습니다. 다음 실제 점검은 A/B 노선별 운행 중 응답, DB 구간 커버리지, 기흥구/강남구 시간별 예보, 실제 기록에 대한 예측 오차입니다.

### 동작과 제한

- XLSX는 Python 표준 라이브러리로 직접 읽습니다. Excel 설치, 수동 CSV 변환, pandas/openpyxl 설치는 필요 없습니다.
- 24~25시·25~26시 기록은 운행일 다음날 0시·1시로 정규화합니다.
- 출처·표본 수·평균/중앙값을 구분하여 표시합니다. 배차 집계는 차량 두 대의 ETA 차이이며 반복 조회를 포함하므로 실제 운행 시간표로 표시하지 않습니다.
- 집계표에는 만석 빈도와 p75가 없으므로 이를 만들어내지 않습니다. 해당 집계를 쓰는 추천의 만석 추가 대기는 미계산으로 표시하고 등급을 주의로 제한합니다.
- 자료 부족으로 추천을 못하더라도, 선택한 정류장의 실제 혼잡도·배차·좌석을 비교할 수 있습니다. 이것을 도착 가능한 BEST 추천으로 표시하지 않습니다.
- 기흥역→신논현역 내부 소요시간에만 기존 날씨 가중치를 적용하고 전후 구간은 그대로 유지합니다. 새로 읽은 CSV만으로 날씨 계수를 재학습하지 않았습니다.
- BEST/2위/3위 카드의 상세 전환과 기흥구·강남구 날씨 분리는 유지됩니다.

### 제출 완료에 필요한 정확한 원본

GitHub main에는 **`data/realtime.db`가 없습니다.** `busflow.db`는 혼잡도만 있고, `weather.db`는 날씨만 있습니다. XLSX에 보존된 이동시간은 서울 시내 일부 구간이며 기흥역↔서울 및 용인 쪽 전체 구간을 복원할 수 없습니다.

PC에 있는 `data/realtime.db`의 `realtime_location`(차량·시각·정류장·순번) 또는 실제로 작성된 구간 소요시간 자료가 필요합니다. 기흥→신논현의 `travel_time_stats`만 있으면 그 구간만 계산되며, 다른 승하차 지점에는 추가 구간 기록이 필요합니다. 파일을 제공받으면 DB를 덮어쓰지 않고 실제 후보별 도착시간 검증을 이어갈 수 있습니다.

단독 HTML 원본의 `standaloneTravelMinutes()`에는 55/58/61/64분 등의 데모 기준값이 있었습니다. 이 값은 실제 구간 데이터가 아니므로 이번 통합본의 추천에 사용하지 않습니다.

검증: 실제 XLSX 회귀검사 8개, 기존 통합 로직 검사 19개, UI 이벤트 검사. GitHub CI에서 기존 날씨 검사와 실제 Chromium 브라우저 검사를 함께 실행하도록 추가했습니다. 브라우저 카드 상호작용의 테스트용 후보는 테스트 코드에서만 사용합니다. 실서비스의 추천으로 주입하지 않습니다. 실시간 버스·외부 날씨 API 실호출과 실제 전체 출퇴근 소요시간 검증은 미완료입니다.
